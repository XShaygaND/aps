# Описание имитационной модели

[Первичные артефакты](../README.md)

## Правила обработки

1. Движок извлекает ближайшее событие календаря и устанавливает модельное время `now`. Событие `ARRIVAL` имитирует формирование кадра камерой. Отдельного периодического сканирования нет.
2. Источник создаёт заявку, диспетчер постановки помещает её в буфер. Даже при свободном приборе заявка сначала ставится в буфер и затем может быть выбрана при том же `now`.
3. Поиск свободного места выполняется **по кольцу** (Д1ОЗ1): начиная с `bufferPointer`, обход слотов. Если место найдено — запись и сдвиг указателя. Если буфер заполнен — выбивается **самая старая** ожидающая заявка (Д1ОО3), на её место пишется новая. Отказ относится к источнику удалённой заявки. Обслуживаемые заявки не прерываются.
4. После поступления или завершения обслуживания движок вызывает диспетчер выбора.
5. Из буфера выбирается заявка по **LIFO** (Д2Б2): последняя поступившая (максимальный `createdAt`, при равенстве — больший ID).
6. Свободный прибор ищется **по кольцу** от `workerPointer` (Д2П2). Только успешное назначение передвигает указатель на позицию после выбранного прибора.
7. При назначении заявка удаляется из буфера, начинается обслуживание, планируется `COMPLETION`. Время обслуживания ~ Exp(μ) (ПЗ1).
8. Завершённая заявка освобождает прибор. Если в буфере есть заявки и есть свободные приборы — продолжается выбор.

### Принятые соглашения

- Источники имеют номера от 1 до N.
- Индексы приборов и ячеек буфера — от 0. Начальные значения `bufferPointer` и `workerPointer` — 0.
- `RequestId` — пара `(sourceId, sequenceNumber)`.
- Интервалы генерации: Uniform[aᵢ, bᵢ] (ИЗ2).
- Время обслуживания: Exponential(μⱼ) (ПЗ1).

## Календарь событий

| Тип | Когда планируется | Действие |
|---|---|---|
| ARRIVAL | При генерации следующего кадра источника | Создать заявку, поставить в буфер, запланировать следующий ARRIVAL |
| COMPLETION | При старте обслуживания | Освободить прибор, зафиксировать статистику, вызвать выбор |

## Статистика (ОР1)

По каждому источнику:
- число сгенерированных заявок;
- число отказов (выбитых);
- вероятность отказа Pотк;
- среднее время пребывания Tпреб;
- среднее время ожидания Tож;
- среднее время обслуживания Tобсл;
- дисперсии Tож и Tобсл.

По каждому прибору:
- коэффициент использования Kисп = суммарное время занятости / общее время реализации.

Точность: относительная 10 %, доверительная вероятность 0,9. Число реализаций определяется итеративно по формуле для N.

## Отображение (ОД1)

В пошаговом режиме после каждого события:
- календарь событий (ближайшие ARRIVAL и COMPLETION);
- содержимое буфера (ячейки, указатель);
- состояние приборов (свободен / занят, текущая заявка, finishAt);
- текущее модельное время и журнал действий шага.

## Контрольный сценарий (фрагмент)

B = 3, M = 2 прибора, 2 источника.

| t | Событие | Состояние |
|---|---|---|
| 0,00 | ARRIVAL 1.1 | Буфер пуст → сразу на прибор 0; pointer=1 |
| 0,50 | ARRIVAL 2.1 | Прибор 1 свободен → на прибор 1; pointer=0 |
| 1,00 | ARRIVAL 1.2 | Оба заняты → в буфер (ring pos 0); pointer=1 |
| 1,20 | ARRIVAL 2.2 | В буфер (pos 1); pointer=2 |
| 1,40 | ARRIVAL 1.3 | В буфер (pos 2); pointer=0; буфер полон |
| 1,60 | ARRIVAL 2.3 | Выбита самая старая (1.2); 2.3 на её место |
| 2,00 | COMPLETION 1.1 | LIFO → выбирается 1.3 → прибор 0; pointer=1 |
| … | … | … |

## Структуры данных

| Тип | Данные и назначение |
|---|---|
| `SourceSnapshot` | Номер, параметры Uniform, последний sequenceNumber |
| `RequestSnapshot` | ID, источник, createdAt, status, временные отметки |
| `BufferSnapshot` | Массив слотов + bufferPointer |
| `WorkerSnapshot` | ID, текущая заявка, finishAt |
| `WorkerPoolSnapshot` | Состояния приборов + workerPointer |
| `JournalEntry` | Время, ActionKind, ID заявки, прибор |
| `ActionKind` | GENERATED, REJECTED, BUFFERED, SELECTED, STARTED, COMPLETED |
| `StatisticsSnapshot` | Счётчики, вероятности, времена, загрузка |
| `StepSnapshot` | now, событие, снимки компонентов, календарь, журнал |
| `StatisticsReport` | Итоговая таблица ОР1 |

`PlacementDispatcher.place()` возвращает выбитую заявку или `null`.  
`SelectionDispatcher.dispatch()` выбирает LIFO-заявку и свободный прибор по кольцу.
